# DeployDiff

두 폴더를 번갈아 열면서 무엇이 바뀌었는지 찾는 일을 줄이려고 만든 작은 데스크톱 프로그램입니다. 왼쪽에는 기존 자료를, 오른쪽에는 새 자료를 넣습니다. 폴더를 비교하다가 궁금한 파일을 더블클릭하면 같은 화면에서 내용을 확인할 수 있습니다.

이번 소스는 새로 시작한 첫 실행 버전입니다. 문서는 이 README 하나에 모았습니다. 파일을 서버로 업로드하지 않고 선택한 로컬 경로를 읽으며, 원본을 수정하거나 복사하지 않습니다.

## 다운로드

Windows 사용자는 Release 페이지의 Assets에서 `DeployDiffSetup.exe`를 다운로드해 실행하면 됩니다. 설치 과정에서 원하는 설치 위치를 선택할 수 있고, 설치가 끝나면 시작 메뉴 또는 설치 폴더에서 DeployDiff를 실행할 수 있습니다.

개발 중에는 `DeployDiff.exe`도 만들지만, 사용자에게 배포하는 파일은 설치 파일인 `DeployDiffSetup.exe` 하나로 둡니다. 이렇게 하면 다운로드한 사람이 설치 위치를 직접 고를 수 있고, 나중에 바로가기나 삭제 기능도 자연스럽게 관리할 수 있습니다.

## 개발 환경에서 실행하기

Python 3.11 이상을 사용합니다. 압축을 풀면 나오는 `compare-start` 폴더에서 실행하세요.

Windows CMD에서는 다음 명령을 사용합니다.

```cmd
py -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python main.py
```

Ubuntu나 WSL에서는 다음과 같습니다. WSL은 Linux GUI 창이 열리는 환경이어야 합니다.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

한글이 네모로 보인다면 Ubuntu에 한글 글꼴을 설치한 뒤 프로그램을 다시 실행하세요.

```bash
sudo apt update
sudo apt install fonts-noto-cjk
fc-cache -f
```

Qt가 xcb 라이브러리 부족을 안내한다면 Ubuntu에서 `sudo apt install libxcb-cursor0`로 해당 의존성을 설치할 수 있습니다. 다른 이름의 라이브러리를 안내하는 오류라면 그 메시지를 확인해야 합니다.

## 화면 사용법

처음에는 왼쪽에 `samples/left`, 오른쪽에 `samples/right`를 선택해보세요. `config/`와 그 안의 설정 파일은 변경, `added.txt`는 추가, `removed.txt`는 삭제, `same.txt`는 동일로 나타납니다. 설정 파일을 더블클릭하면 포트 변경과 timeout 줄 추가를 확인할 수 있습니다.

좌우 영역에 파일 또는 폴더 하나씩 넣습니다. 선택 버튼을 누르거나 영역에 드래그해 놓을 수 있고, 경로를 붙여넣은 뒤 Enter를 눌러도 됩니다. 양쪽 경로가 준비되면 자동으로 비교합니다. 새로운 대상을 비교하고 싶을 때는 위쪽의 `새 비교`를 누르면 화면이 처음 상태로 정리됩니다.

폴더를 선택하면 하위 경로를 모두 나열합니다. 이름 뒤의 `/`는 폴더 표시입니다. 같은 상대 경로는 좌우 같은 행에 나타나고, 한쪽에만 있는 항목의 반대쪽은 빈칸입니다. 아직 폴더를 접고 펼치는 트리는 없으며 전체 상대 경로로 위치를 확인합니다.

| 표시 | 의미 |
| --- | --- |
| 동일 | 두 파일의 바이트가 같거나 폴더 아래에 차이가 없음 |
| 변경 | 파일 내용 또는 항목의 종류가 다름. 폴더라면 내부에 차이가 있음 |
| 추가 | 오른쪽에만 존재 |
| 삭제 | 왼쪽에만 존재 |
| 오류 | 읽거나 비교하지 못한 항목 |

빈 폴더의 추가와 삭제도 표시합니다. 이름을 바꾸거나 이동한 파일은 기존 위치의 삭제와 새 위치의 추가로 나옵니다. 심볼릭 링크는 따라가지 않고 링크에 저장된 대상 경로 문자열을 비교합니다. 접근하지 못한 디렉터리가 있으면 결과를 동일하다고 판단하지 않고 비교 실패를 알립니다.

하단의 `같은 항목`은 동일한 행, `다른 항목`은 변경·추가·삭제·오류 행을 보여줍니다. `전체 보기`를 누르면 숨겼던 행이 다시 나타납니다. 이 버튼들은 원본 파일에 영향을 주지 않습니다.

텍스트 파일을 더블클릭하면 좌우 줄 번호와 내용을 보여줍니다. 파일 두 개를 직접 선택해도 이 화면으로 열립니다. 중간에 추가된 줄은 반대쪽을 비워 이후 줄 번호가 달라도 내용을 나란히 확인할 수 있습니다. 노랑은 변경, 초록은 추가, 빨강은 삭제입니다. 폴더에서 들어왔다면 ‘폴더로 돌아가기’를 눌러 목록으로 복귀합니다.

줄바꿈은 `↵`, CR 문자는 `␍`로 표시합니다. 마지막 줄바꿈의 유무와 Windows/Linux 줄바꿈 차이도 비교 대상입니다. UTF-8, BOM이 있는 UTF-16, CP949를 읽습니다. 인코딩만 달라 실제 바이트는 다르지만 화면에 표시되는 글자는 같을 수 있습니다. 이때 상단에는 파일 변경이 표시되고 줄 비교는 동일하게 보일 수 있습니다.

바이너리 파일이나 읽을 수 없는 인코딩은 내용 동일 여부까지만 제공합니다. 텍스트 내용 표시는 파일당 2 MiB, 10,000줄까지입니다. 이는 첫 버전에서 너무 많은 줄을 표에 한꺼번에 넣지 않기 위한 제한입니다. 폴더 전체 비교에는 이 크기 제한을 적용하지 않습니다.

Windows 탐색기와 WSL의 GUI 사이에서는 드래그 전달이 되지 않을 수 있습니다. 그 경우 선택 버튼이나 경로 붙여넣기를 사용하세요. Linux에서 `C:\...`를 붙여넣으면 기본 WSL 마운트 규칙인 `/mnt/c/...`로 바꿉니다. 드라이브를 다른 위치에 마운트했다면 Linux 경로를 직접 입력해야 합니다.

## 코드를 나눈 이유

`engine.py`는 폴더와 파일을 읽고 결과를 만듭니다. 파일 크기가 다르면 바로 변경으로 판단하고, 크기가 같으면 1 MiB씩 읽어 바이트를 비교합니다. 텍스트 줄 정렬에는 Python 표준 라이브러리의 `difflib`를 사용합니다.

`main.py`는 좌우 입력 영역과 결과 표시를 담당합니다. PySide6는 Python에서 Qt 창과 버튼을 만드는 라이브러리입니다. 파일 읽기는 QThread에서 실행하고 결과는 신호로 화면에 전달합니다. 이 구조는 [Qt의 QThread 문서](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QThread.html)를 참고했습니다. 비교 중에도 창의 이벤트를 처리할 수 있지만, 큰 결과를 표에 넣는 순간에는 지연될 수 있습니다. 취소 기능은 아직 없으므로 비교가 끝난 뒤 종료합니다.

검증은 프로젝트 폴더에서 실행합니다. 별도 테스트 패키지는 필요하지 않습니다.

```bash
python -m unittest -v test_engine
```

자동 테스트는 폴더 상태 전파, 빈 폴더, 줄 삽입 정렬, 줄바꿈 차이, 바이너리 제한, 한쪽에만 있는 텍스트와 잘못된 입력 등을 확인합니다. 실제 운영체제의 파일 선택과 드래그는 직접 창을 열어 확인해야 합니다.

제작 환경에서 엔진 테스트 7개는 통과했습니다. GUI 테스트 코드 `test_gui.py`도 포함했지만 해당 환경에 `libEGL.so.1`이 없어 실행 검증을 완료하지 못했습니다. Qt를 실행할 수 있는 환경에서는 `python -m unittest -v test_gui`로 폴더 비교, 파일 열기, 필터, 목록 복귀를 확인할 수 있습니다. 실제 Windows/WSL 화면과 드래그 동작은 추가 확인이 필요합니다.

## 배포하기

배포 파일은 Windows CMD에서 만듭니다. `build.bat`은 PyInstaller로 `dist\DeployDiff.exe`를 만들고, `build-installer.bat`은 Inno Setup으로 `dist\DeployDiffSetup.exe`를 만듭니다.

```cmd
build-installer.bat 0.0.2
```

GitHub Release까지 한 번에 올릴 때는 GitHub CLI 로그인 후 아래 명령을 사용합니다.

```cmd
release.bat 0.0.2
```

Release에는 `DeployDiffSetup.exe`만 올립니다. `DeployDiff.exe`는 설치 파일 안에 들어가는 실행 파일이고, `build`, `dist`, `.spec`, `.venv`는 GitHub 코드 저장소에 올리지 않습니다.

현재는 폴더·파일 비교와 내용 확인까지를 목표로 합니다. 비교 도중 원본이 바뀌는 상황에 대한 스냅샷 보장은 없으므로 변경이 끝난 자료를 선택해주세요. 파일 편집, 병합, 압축파일 내부 비교는 포함하지 않았습니다.
